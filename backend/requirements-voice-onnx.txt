# Zaram backend - voice extra, ONNX runtime. Install with:
#
#     pip install -r backend/requirements-voice-onnx.txt
#     python -m spacy download en_core_web_sm
#
# This is `requirements-voice.txt` with the tensor library swapped, not a
# different engine. Same Kokoro-82M weights, same 54 voices, same Apache-2.0,
# same output - see `voice/providers/kokoro_onnx.py` for what the swap costs
# (one graph patch, to recover the per-phoneme durations lip sync reads).
#
# What comes out, measured on disk in backend/venv on 19 August 2026:
#
#     torch          494 MB      - the whole reason this file exists
#     transformers    96 MB      - reached only through kokoro's KModel
#     tokenizers, safetensors, sympy, networkx, mpmath - torch's own tail
#
# What goes in: onnxruntime, which the *mic* extra already installs because
# faster-whisper depends on it, so on a machine that can listen the marginal
# cost is zero. Plus `onnx` itself, which is needed once, to add an output to
# the exported graph, and never again.
#
# What deliberately stays: spaCy and misaki. They are 125 MB and they are what
# knows that "read" is not "read" and "lead" is not "lead". Dropping them for
# the espeak fallback pinned below saves 97 MB and makes heteronyms wrong out
# loud, which is a bad trade on the half of the stack the user hears.
#
# `spacy-curated-transformers` must NOT be added here, and is worth naming
# because it is not obvious. spaCy loads plugin entry points from whatever is
# installed, that plugin imports torch at module scope, and one contaminated
# virtualenv therefore drags 494 MB back in through a package nobody asked for.
# Found by running the ONNX path in a process where torch was unimportable -
# see `voice/tests/test_kokoro_onnx_backend.py`.
